# Deploy Console 并行任务中心版

Deploy Console 并行任务中心版是在原版之外独立安装和运行的版本，用于在一个主窗口中同时执行多个 Jenkins 打包与部署任务。它不会修改原版程序或原版配置。

界面沿用迁移工具的深色渐变与雾面玻璃卡片，悬停过渡为 200ms，并尊重 Windows 减少动画设置。图标随程序离线打包，来源与许可见 `assets/lucide/LICENSE` 和 `assets/uiverse/SOURCE.md`。

Windows、Linux 和 macOS 共用最新功能：Jenkins 自动登录、完整任务树缓存与搜索、仅打包开关、包号溯源、并行任务中心，以及按产品跳转 Dashboard Pods。各平台保留原生配置目录、凭据加密和浏览器后端。

## 底部可折叠任务中心

- 软件只使用一个主窗口。点击标题栏右侧的“新建任务”或按 `Ctrl+N`（macOS 为 `⌘N`） 会在主窗口内增加独立任务工作区，不再打开新的系统窗口；当前为 SSH 模式时会自动继承目标环境。
- 同一用户配置目录只运行一份应用，重复双击程序会恢复已有主窗口，不再新增托盘图标；正常退出或异常结束后可重新启动。每次更新都必须先通过托盘菜单退出旧版；运行期间不能重命名或替换 EXE，否则延迟加载组件可能发生解压错误。
- 底部任务中心收起时只显示运行数、失败数和任务总数；点击右侧箭头可展开任务列表。
- 点击任务的包号可复制完整内容，也可选中任务后按 `Ctrl+C`（macOS 为 `⌘C`）；环境部署表单在可用高度不足时支持滚动。
- 展开后会显示每个任务的包号或 Jenkins Job、目标环境、当前阶段、被替换包号、总体进度和耗时。点击任意任务行即可切换主工作区。
- “被替换包号”在实际部署开始后后台获取：SSH 根据目标 YAML 定位工作负载并读取其正在运行的容器镜像，云端读取同一部署目标的运行镜像。查询不计入进度，也不阻塞部署；开始删除或提交部署时关闭查询窗口，未及时取到或查询失败显示“未获取”，迟到结果丢弃。多个运行版本全部保留，批量任务部分读取失败会标明“部分未获取”。点击该列或在该列按 Ctrl+C（macOS 为 ⌘C）复制完整旧包号，多个包号一行一个；无包号时不修改剪贴板。记录在本次任务结束后保留，重新执行时清空；仅打包显示“不涉及”。
- 任务行右侧的“停止”用于取消正在运行的 Jenkins 一键任务；等待确认期间显示禁用的“停止中”，确认取消且后台收尾完成后变为“继续”。点击“继续”会按上次启动时的 Job、分支、参数及部署配置重新打包，并重置进度、耗时和日志；不使用后来修改的表单值。仅打包/打包后部署开关也沿用原值，SSH 合批会重新登记。继续所需配置只保留在本次应用会话中。“移除”用于移除已结束或尚未开始的任务，任务中心至少保留一个工作区。
- 新增第二个任务或任一任务失败时，任务中心会自动展开；成功、失败和取消状态同时使用文字与颜色表示。
- 不同 Jenkins 任务可以同时打包；实际并行数量仍受 Jenkins 执行器和任务自身并发设置限制。
- 不同 SSH 或云端目标可以同时部署。
- 默认情况下，相同 SSH 目标或相同云端目标会自动进入安全队列，前一个部署结束后再继续，避免相互覆盖。
- SSH 排队和镜像搬运支持取消；停止受控进程组并确认退出后才释放目标。取消共享批次中的一个任务，会重新组批继续其余任务；已开始的 Kubernetes 删除/应用会完成必要收尾。镜像命令连续 10 分钟无输出或总计超过 60 分钟会停止并报错，其他远端命令最长等待 5 分钟。无法确认远端已停止时保留现场并阻止该目标的后续部署，需检查服务器状态后重启工具。
- SSH 一键任务自动按可共享镜像搬运命令的目标环境合批：多个任务先并行打包，再由一次镜像搬运统一处理本批次包，随后逐个更新并应用对应 YAML。
- 一个任务工作区同一时间只执行一个打包或部署操作；需要并发时必须新增任务，避免日志和状态相互覆盖。
- 点击主窗口右上角“×”会隐藏到系统托盘或 macOS 菜单栏；桌面不支持托盘时改为最小化，后台任务不会中断；单击托盘图标即可恢复。需要真正退出时使用托盘菜单或“配置迁移 → 退出应用”，运行中的任务仍需先结束。
- 所有任务共享并行版配置对象，防止任务之间保存配置时相互覆盖。

项目详细背景、架构、关键约束和开发注意事项见 [HANDOFF.md](HANDOFF.md)。新成员修改代码前必须先阅读该文档。

## 功能

- 浏览 Jenkins 文件夹任务，读取构建参数并记忆每个任务的参数值。
- `CUSTOM_NAME` 右侧的“刷新选项”直接读取当前 Jenkins 任务的最新候选项并更新缓存，保留当前填写值和其他参数；旧缓存中没有的手填值（如 `hbxx`）也不会被替换。刷新失败保留原列表；实际候选项以 Jenkins 配置为准。
- 触发 Jenkins 构建，持续显示控制台日志、预计进度和最终结果。
- 从构建日志中提取镜像包号。
- 通过 SSH 更新镜像清单和 Kubernetes YAML，并执行环境发布命令。
- 管理多套部署环境及其关联的 Kubernetes Dashboard。
- 双击环境名称时使用系统默认浏览器打开环境页面，同时复制已保存的环境密码并提示账号。
- 一键 SSH 部署后使用 Edge（Windows）或 Chrome/Chromium（Linux、macOS）自动登录 Dashboard，并按最终部署包的产品打开对应命名空间的 Pods 页面（如 PQM → `pqm`、ESC → `esc`、ETM → `etm`）；合并部署按环境和产品去重，同一产品前后端只打开一次。失败时回退为默认浏览器并复制 Token，保留本次目标命名空间。手动双击 Dashboard 地址或点击“自动登录”仍默认打开 `etm`。
- 登录鼎捷 Ops 平台，选择部署专案、服务类型和云区节点后发布 Jenkins 构建包。
- Ops 云端部署成功后自动打开 Rancher Pod 状态页，并使用已保存的账号密码登录。
- Dashboard 与 Rancher 自动登录成功后只更新状态和日志，不再显示需要确认的成功提示框。
- 支持 Jenkins 一键打包后转 SSH 环境部署或 Ops 云端部署。
- 支持取消 Jenkins 排队或构建，并确认线上任务真实停止。
- Jenkins、SSH 和 Ops 运行失败时，错误提示固定显示在当前任务工作区内，不再弹出独立系统对话框打断其他并行任务。

## 环境要求

- Windows 10/11、macOS 13+，或 Linux 桌面（Ubuntu 24.04 / Deepin 25 AMD64）
- Python 3.11/3.12（仅源码运行和本机打包需要）
- Windows 使用 Microsoft Edge；macOS/Linux 使用 Google Chrome 或 Chromium
- 可访问目标 Jenkins、SSH 环境、Dashboard 和 Ops 平台的网络

安装依赖：

```powershell
python -m pip install -r requirements.txt
```

## 本地运行

```powershell
python main.py
```

应用配置按平台保存于：

```text
Windows: %APPDATA%\BuildDeployToolParallel\config.json
macOS:   ~/Library/Application Support/BuildDeployToolParallel/config.json
Linux:   ${XDG_CONFIG_HOME:-~/.config}/BuildDeployToolParallel/config.json
```

Windows 首次启动并行版时会只读复制原版 `%APPDATA%\BuildDeployTool\config.json`，之后仅保存到并行版目录。

Windows 凭据使用 DPAPI 加密；macOS 和 Linux 使用仅当前用户可读写的本地密钥文件加密，避免 Keychain 或桌面 Secret Service 未启动、未解锁时阻塞登录按钮。不同操作系统之间不能直接迁移已保存的密文凭据，需要重新输入密码和 Token。

## 基本使用

### Jenkins 打包

1. 首次使用时填写 Jenkins 地址、账号和密码或 API Token，然后点击“登录并加载”。每次登录先向 Jenkins 验证身份，成功并加载任务后显示“登录成功”，三端均收起连接栏；失败保持展开并显示具体错误（如 HTTP 401、403 或连接异常），已有本地缓存不会被当作登录成功。
2. 三端均会在凭据完整时自动登录：身份验证通过后只读取任务树，已有任务树缓存则直接复用。构建参数和分支在首次点击具体任务时读取并缓存，之后点击、新建任务或重启均优先复用缓存；不会在启动时遍历所有任务预加载，也不会等待云端目标读取。
3. 点击搜索框右侧的刷新按钮只更新完整任务树，不受当前搜索结果限制，已有参数和云端目标缓存保留。分支使用参数旁的“刷新分支”更新，云端目标使用对应刷新按钮更新。缓存按平台地址和账号隔离，不会跨服务器误用。
4. 三端均可模糊搜索根任务下的二级模块，命中模块的全部子任务会保留在结果树中。
5. 在任务树选择最终构建任务并设置构建参数；SSH 环境部署时默认收起，外部保留可编辑的 `CUSTOM_NAME` 和 `GIT_BRANCH2` 及刷新按钮，任务没有 `GIT_BRANCH2` 时保留 `GIT_BRANCH`。较长说明可悬停查看，点击标题可展开全部参数。云端模式收起时仍显示 `GIT_BRANCH`；切回 SSH 时自动收起，填写值不变。修改或刷新不会展开其他参数；同时存在两个分支字段时共用一个“刷新分支”按钮及候选列表（折叠时，SSH 模式位于 `GIT_BRANCH2` 右侧，云端模式位于 `GIT_BRANCH` 右侧；展开时按钮纵向跨相邻的两个分支字段），只发起一次请求并保留各自填写值。`GIT_BRANCH2` 留空时仍由二开打包流程使用 `GIT_BRANCH`。首次读取失败时，再次点击该任务可重试。
   云端部署目标配置可点击标题收起。“状态集”默认展开，打包前不加载历史记录；本工具发起打包并取得构建编号后，显示本次结果、实际分支、提交版本和 Changes 变更记录，构建中每 5 秒更新，完成后停止。切换模块或任务时只显示各自本次打包记录；排队取消且未取得编号时不显示其他构建。手动刷新和“在 Jenkins 查看”始终对应本次编号，记录仅保留在当前程序会话。
6. 选择 `SSH 环境部署` 或 `云端部署`；关闭“打包后部署”开关时仅执行 Jenkins 打包。

Jenkins 打包页与包号溯源页的任务树搜索框均不显示清除按钮，搜索内容由用户手动删除。任务树中的目录可点击整行展开或收起，也可选中后按 `Enter`、`Space` 操作，不必精确点击左侧箭头。选择模块或具体服务时，Jenkins 页和云端部署页的部署专案自动切到对应模块；WEB/SERVICE 任务同时匹配前端/后端，APP 任务匹配对应的 mobile 专案及前端，例如 ETM 的 `2-APP` 对应 `etmmobile`。目标仍可手动修改，APP 任务可使用同系统的 mobile 专案，其他系统仍禁止混用。模块文件夹不加载构建参数。
7. 点击当前模式对应的执行按钮。

Jenkins 任务路径和打包操作栏固定在右侧顶部，滚动配置、状态集和日志时仍可操作。顶部页签可按住拖动排序，顺序同步到其他任务并在重启后保留；自动跳转始终进入对应功能页。

### 包号与环境溯源（第四个页签）

1. 进入“包号溯源”，每行粘贴一个包号，最多 20 个，直接查询 Jenkins 构建来源。标准格式为 `镜像名:版本号`，例如 `pqmmobile-bmgd-2.1.0:4.0.0.1000.10007`，也兼容横杠连接平台版本和数字包版本的格式。可保留完整仓库路径，结果保留输入的包号格式。
2. **Jenkins**：复用 Jenkins 页登录，默认自动按包号的产品和服务筛选任务：`backend → SERVICE`、`frontend → WEB`、`mobile / mobilefrontend → APP`。例如 `etmbackend` 只查 ETM 后端，`pqmmobile` 只查 PQM 的 APP，覆盖普通、云应用和二开任务；批量查询分别按每个包筛选。左侧任务树复用打包页的搜索和刷新缓存，右侧保留包号输入与查询结果。选中具体任务后只查该路径；左侧搜索框不显示清除按钮；手动删空搜索内容或再次点击已选任务即可取消选择，立即恢复按包号自动匹配。搜索后已选任务不在可见结果中时，也会取消路径限制。溯源选择与打包页当前任务相互独立。内部保持每任务最近 500 次、每份日志最多 32 MB 的读取上限。
3. 点击“查询来源”。列表、详情和“复制结果”只包含五项：包号、打包人、打包分支、打包时间、代码仓库。可随时取消并保留已找到的记录；“查看构建”打开选中记录的 Jenkins 页面。
4. 打包人读取该次构建的触发用户，缺失时尝试日志开头的用户记录，仍缺失则显示“未记录”。时间为 Jenkins 构建记录时间（UTC+8）；分支和仓库来自同次构建的 SCM / checkout 记录，多仓库用对应编号列出。仓库包含 `${CUSTOM_NAME}` 等变量时，只有同一提交、分支及地址格式对应的 checkout 记录才能替换为实际地址。
5. 只有镜像推送证据时，除包号外的四项显示“未确认”。同一包号的多次构建全部保留；短包号可能对应不同镜像仓库，可通过“查看构建”核对。
6. 历史构建通过任务的 `/api/json?tree=allBuilds[number,timestamp,result,building]{起始位置,结束位置}` 分页读取，再读取对应构建的 `consoleText` 和源码元数据。普通 `builds` 默认只返回最近 50 次；`allBuilds` 可以查询更早但仍被保留的构建，无法恢复已清理记录。包号末尾数字不是 Jenkins 构建编号，不能直接替代。

查询仅使用只读接口，不触发构建、拉取或部署镜像，不保存原始构建日志。超过查询上限、日志读取失败或记录已被清理时可能查不到；状态行会说明是否查全，鼠标停留可查看原因，“未找到”不代表包不存在。按钮从左到右为“查看构建、取消查询、复制结果、查询来源”，整组按钮位于包号输入框下方靠右，查询按钮在最右侧。

切换“溯源方式”为“环境溯源”，即可从下拉框选择云区；已有云区优先读取缓存，无缓存时后台加载，也可点击“刷新云区”。再在左侧选择具体 WEB、SERVICE 或 APP 任务并点击“查询来源”。选任务后保留仍受支持的云区；不支持时清空选择并提示重选，不会自动切到其他云区。云区复用 Jenkins 页的下拉组件及目标缓存，账号使用“云端部署”页的 Ops 登录信息；APP 自动对应 mobile 专案的前端。查询时重新读取精确部署目标和 Ops 当前运行镜像，再按镜像包名与版本查询该 Jenkins 任务。环境及完整运行镜像合并显示在下方结果详情中，即使构建记录已清理也能查看、复制；不会把部署历史当作当前包，也不表示已逐个核对所有 Pod。切换任务、云区、模式或账号会使旧结果失效。

### SSH 环境部署

1. 在“环境部署与 Dashboard”页新增 Dashboard。
2. 新增部署环境并关联 Dashboard。
3. 修改包号后，离开输入框或按回车，工具会识别后端、前端或移动端包（`mobile` 和 `mobilefrontend` 均支持，例如 `pqmmobile` 对应 `/data/yaml/app/mobile/pqmmobile.yaml`），并同步两页的 YAML 目录、YAML 文件和应用命令；这些临时值只有在用户主动保存环境时才会写入配置。失焦仅进行本地 SSH 配置更新，无效或未输完的包号保留原配置；回车仍可继续匹配云端目标。
4. 核对镜像目录、镜像清单、YAML 和执行命令。
5. 保存环境配置后，从 Jenkins 页执行一键流程，或在环境页直接执行部署。

仅执行环境部署时，包号框支持每行一个包，可直接粘贴多行；`Shift+Enter` 换行，回车或失焦校验。多个包共用当前环境和删除开关；预览列表列出各包的 YAML，点击某行可查看并编辑该包的删除命令。按应用前缀判重（如 `etmbackend`），同一应用的客户名、版本不同仍视为重复，整批不会启动；同一产品的 `mobile` 与 `mobilefrontend` 也视为同一移动端应用，前端与移动端可以一起部署。

手动多包作为一个任务执行：先校验所有 YAML，再用独立的多包清单执行一次镜像搬运脚本，目标仓库已有的镜像跳过搬运。所有镜像准备完成后统一更新 YAML；关闭删除开关时分别应用，开启时先全部删除、再分别应用。启动后包号、目标和命令均固定；后续修改表单不影响本轮部署。

搬运或 YAML 更新失败时不进入删除/应用阶段。删除中途失败会停止后续删除，并重新应用已尝试删除的 YAML（含失败项）以恢复资源；恢复使用本次包版本，并非回滚旧版本。应用失败仍继续处理其他包，日志逐包列出结果，整批标记失败。开始删除后会完成必要的应用收尾；这些规则仅用于手动多包部署，单包和 Jenkins 合批流程沿用原行为。

“删除后重新应用”使用与“打包后部署”相同的滑动开关，首次使用默认关闭，切换后自动记住选择，重启或新建任务时恢复；已打开的其他任务保留自己的设置。TAB1 和 TAB2 共用开关和可编辑的删除命令。命令默认随包号、任务路径和 YAML 文件生成，手动修改在当前任务中按主机、端口、YAML 目录和文件保留，启动部署时固定为本次执行命令；切换到其他目标时不会套用旧目标的修改。TAB1 折叠时仅在配置标题右侧显示开关，展开时开关和命令位于表单左下方；TAB2 位于表单右下方。

单包和 Jenkins 合批开启此选项后，在镜像准备完成、YAML 更新后执行命令框中的删除命令，再执行应用命令；默认命令为 `kubectl delete -f <当前 YAML>`，仅替换 YAML 文件名，不自动追加参数；手动编辑后按命令框内容执行。删除失败则停止后续应用并记录错误。开关开启但命令为空时禁止启动。删除与应用分别记录耗时。每个任务启动时冻结自己的选项和目标，合批也逐个执行；删除已经开始时，取消操作会等待紧接着的应用完成，避免停在资源已删除的状态。删除成功但应用失败时会明确提示，需检查后重试。

执行 SSH 环境部署时，每个任务都会在镜像目录下创建独立的临时工作目录和镜像清单，复用原拉取脚本后立即清理。不同产品可以并行搬运镜像，不会再争用或覆盖环境保存的公共镜像清单。

SSH 镜像搬运期间，部署日志会过滤终端动态重绘字符，并区分显示从源仓库拉取、向目标仓库推送的传输进度。远程输出采用大块高速读取和节流刷新，避免大量 Docker 进度行拖慢 SSH 通道；日志还会记录镜像拉取及推送耗时与部署总耗时。

日志保留每层 `Downloading / Extracting / Pushing` 的真实字节数和文本进度条，同一层的连续刷新每秒合并一次，阶段切换和命令结束时补齐最新值；合批日志按镜像归属显示到对应任务。连续 10 秒没有新的进度或状态时，每 10 秒提示“多久未收到远端输出、多久无进度或状态变化”。重复重绘相同数值不算进展；提示只说明观测到的等待，不保证远端仍在推进，也不直接判定卡死。

合批中的每个任务独立显示镜像搬运进度：尚未轮到的包显示“等待拉取镜像”，正在处理的包按 Docker 多层字节进度显示拉取或推送的估算百分比；已存在的目标镜像跳过搬运。任务中心百分比仍表示从打包到部署的整个流程，只有对应包推进时才更新。传输阶段完成需有 Docker 完成记录；脚本结束后仍需校验目标镜像并应用 YAML，才显示部署完成。Dashboard 自动登录失败会单独提示，不会将已完成的部署误报为失败。

SSH 密码认证最多等待 30 秒，以兼容认证响应较慢的目标环境；网络连接和服务握手仍分别限制在 15 秒内，避免不可达主机长时间阻塞任务工作区。

Jenkins 页选中具体任务后，立即在本地预览 YAML 目录、文件和应用命令；切换服务器环境时仍保留所选任务的预览。自动预览无需保存，也不覆盖已保存配置或清除其他未保存修改。“保存环境配置 / 刷新”按钮位于配置区右侧。一键 SSH 流程以最终包号再次校验，若与启动时预览不一致则停止部署并提示。目标 Harbor 已存在完全相同的镜像时会跳过重复拉取和推送；同一环境的 Jenkins 构建可并行，但 SSH 镜像搬运和 YAML 发布会安全排队，避免共享镜像清单相互覆盖。

SSH 一键任务开始后会自动登记批次，无需开关或再次确认。程序按 SSH 主机、端口、账号、镜像目录、镜像清单和拉取命令判断是否可合批，等待本批次所有已登记任务打包完成后自动生成一份多包镜像清单统一搬运。若新任务进入时上一批处于源镜像拉取阶段，软件会在当前工作区内询问：可继续当前轮，或安全终止受控镜像命令、等待新包完成后重新合批；推送、YAML 修改和 `kubectl apply` 阶段不会中断，只会进入下一轮。需要继续增加任务时，从标题栏点击“新建任务”或按 `Ctrl+N`（macOS 为 `⌘N`） 即可继承当前 SSH 环境。

合批搬运由关闭作业控制的 Shell 启动 `setsid`，再用 Shell `wait` 等待脚本完成并检查其退出码，兼容不支持 `setsid --wait` 的旧主机。脚本非零退出时停止后续镜像确认与 YAML 发布。搬运后的镜像探测会区分仓库返回未找到、认证/权限、DNS、网络、TLS 和 Docker CLI 错误，日志仅显示错误类别与退出码，超时保留最后一次诊断，不显示可能含凭据的原始响应。

服务器搬运脚本应在 `docker login/pull/tag/push` 失败时立即非零退出，例如在脚本开头启用 `set -e`；否则最后一条成功的 `echo` 会掩盖前面的失败。客户端不会自动修改服务器脚本。

同一批次若多个包指向同一个 YAML，最后登记的包生效，较早任务会在部署日志中显示被覆盖提示。不同 YAML 会在镜像统一搬运完成后分别更新并执行各自的 `kubectl apply`。

### Ops 云端部署

1. 在“云端部署”页填写平台地址、账号和密码。
2. 在“云环境部署状态（Rancher）”区域填写 Pod 状态页地址、账号和密码，可先点击“保存并测试登录”验证。
3. 点击“登录并加载部署数据”后，通过 Ops API 加载部署专案、服务类型和云区节点，并打开浏览器填写已保存的账号密码、自动登录 Ops 网页。刷新目标及后台部署仍直接调用 API；网页自动登录失败会提示原因并保留已加载的数据。
4. 首次加载会预先缓存当前云厂商下全部专案的服务、云区选项，未选择过的专案也会读取；完整缓存支持重启和新建任务复用。点击“刷新云端目标”“刷新三个栏位”或重新登录会全量重新读取。缓存按平台地址、账号、云厂商和专案隔离，个别查询失败保留旧缓存并提示，其他成功专案可正常使用。原云区在新服务中仍有效时保留，否则清空并由用户重新选择。缓存只保存界面选项，实际部署仍通过 API 登录并校验目标和镜像。
5. “云端部署”页的包号默认带出最近的 Jenkins 构建包，可直接编辑，点击“部署此包号”时以该输入框为准。输入后按 Enter 可匹配实际专案和服务类型；例如 `etmmobilefrontend` 对应 `etmmobile / etmmobile 前端`。“环境部署与 Dashboard”页输入包号按 Enter 的联动也继续支持。
6. 提交前会精确校验部署目标和镜像版本，提交后会确认产生新的部署记录，并自动打开 Rancher Pod 状态页登录查看。

为避免重复发布，部署 POST 不会自动重试。如果平台已接收请求但客户端无法确认新记录，界面会显示“部署结果未知”；此时必须先到 Ops 平台核对记录，不能直接重试。

Ops 登录成功后，软件打开或最小化期间会后台维护 API 会话：每 5 分钟校验一次，每 30 分钟按客户端策略重新登录（并非服务端承诺的有效期）。操作前也检查会话，明确登录失效时自动重新登录，安全读取最多恢复重试一次；权限错误和网络故障分别提示。后台维护不修改任务执行结果，也不阻止退出。账号修改后旧会话结果丢弃；云端提交前最后检查取消状态，不重发已提交或结果不明的部署。

## 打包

Windows：

```powershell
.\build.bat
```

Windows 当前发布入口统一为 `release/DeployConsoleBatchSafe.exe`；对应源码、资源与测试保留在项目根目录。打包脚本在发现应用进程仍运行时拒绝构建，退出后才更新入口并执行凭据和 Selenium 自检。手动发布也必须先确认进程退出，不能采用运行期间重命名旧 EXE 再放入新版的方式。

macOS（必须在 Mac 上执行）：

```bash
bash ./build-macos.sh
```

Linux（在目标发行版和 CPU 架构上执行）：

```bash
bash ./build-linux.sh
```

Deepin 25（保留原打包入口，复用 Linux 构建）：

```bash
bash ./build-deepin.sh
```

对应产物：

```text

macOS:   dist/DeployConsoleParallel.app、dist/DeployConsoleParallel-macos.dmg
```

Linux 与 macOS 可通过 `DEPLOY_CONSOLE_VENV` 指定构建虚拟环境。Linux 包受构建机的 glibc 和 CPU 架构约束；当前 Ubuntu 24.04 x86_64 包不承诺兼容旧版发行版。Linux 桌面需具备 Qt 所需的系统运行库和中文字体。本次 WSL 构建日志提示 `libxcb-*`、`libxkbcommon-x11` 等未收集，客户桌面需提供这些运行库；离屏启动检查不替代真实 X11/Wayland 和浏览器验收。macOS 的 Intel 与 Apple Silicon 版本分别在对应架构上构建。

macOS 正式分发前应设置 `CODESIGN_IDENTITY` 完成签名，并按组织发布流程执行 Apple 公证。

## 部署耗时日志

- Windows 自动写入 `D:\AI\tool\deployment-tool-parallel\log`；macOS/Linux 写入应用或源码目录下的 `log`。每次启动生成 `deployment-时间-进程号-随机标识.log`，无需额外操作。
- UTF-8 JSON 行日志按 `task_number` 和 `run_id` 区分任务；`batch_link` 关联合批成员与执行任务。记录 Jenkins 提交/等待、目标排队、合批等待、SSH/SFTP、镜像搬运与校验、YAML 更新和应用的耗时。
- Docker 镜像层状态变化立即记录，字节进度与无输出等待每 10 秒采样；`transfer_context_end` 给出单镜像拉取/推送阶段耗时，`image_push_complete` 到 `yaml_apply` 的间隔可定位先完成镜像等待其他包的时间。只有远端输出包含相应状态时才能区分下载和解压；本日志不采集远端 CPU、磁盘或网卡指标。
- `task_end` 包含总耗时和阶段汇总。阶段存在嵌套与并行，不能把所有 `duration_s` 直接相加；合批跟随任务的 `batch_wait` 包含等待执行任务部署完成的时间。Jenkins 排队与构建可结合 `pipeline_phase` 时间戳和 `jenkins_duration_ms` 区分。
- 异步写入，每文件 10 MB、保留 3 份轮转备份；不同启动生成的文件需按需清理。只记录允许的诊断字段，不写配置、构建参数、原始控制台输出或命令，敏感字符串会被过滤。日志写入失败不阻断部署，队列满时丢弃诊断事件。
- 新版启动后才开始记录，已结束的旧任务无法补录。可执行 `DeployConsoleBatchSafe.exe --self-test-diagnostics` 验证日志模块（仅临时合成数据，无真实部署）。

## 安全提示

- 云端部署和 SSH 部署会改变运行环境，操作前必须核对目标和包号。
- 不要在源码、文档、日志或提交中写入密码、Token 和其他凭据。
- 不要绕过现有确认弹窗、环境保存检查和目标完整性检查。
- Ops 页面结构变化时应增强定位与错误上下文，不能静默选择其他包或区域。

## 平台说明

- PyInstaller 不能跨操作系统生成原生包：Windows EXE、macOS `.app` 和 Linux ELF 必须分别在对应系统构建。
- 当前已验证 Windows 与 Ubuntu/WSL AMD64 构建；Deepin 包目标为 Deepin 25 AMD64，仍建议在真实 Deepin 25 桌面执行一次浏览器与剪贴板验收。
- macOS 构建脚本已就绪，但必须在真实 Mac 上生成并验证 `.app/.dmg`；未签名包可能被 Gatekeeper 阻止。
- macOS 与 Linux 首次使用时需要重新录入原 Windows 配置中的密码和 Token。
